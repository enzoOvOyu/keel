# SSH 凭据主密钥维护（WP-1.6）

此功能维护数据库中项目 SSH 私钥的加密存储，不轮换目标 authorized_keys，也不改变公钥、credential_ref/version、有效期、撤销状态或 Execution 快照。接口只在 owner CLI 提供；浏览器/API不接收主密钥或明文私钥。新代码/051迁移尚未在运行库启用，新增用例留待用户要求的 P1 集中验证。

## 存储契约

- 主密钥仍为独立受保护的32随机字节文件，Load不跟随最终符号链接，要求当前用户拥有的私有普通文件。`key_id` 是带专用域的 SHA256 指纹，标识存储代际，不是密钥本身。
- `credential-master-inspect` 在一致数据库快照中认证全部历史密文与完整关联身份，包括已过期/撤销记录；仅返回指纹、注册代际、数量及认证结果，不返回 signer/明文。维护校验允许历史身份，不改变正常 Open 的有效期限制及 Provider 的撤销限制。
- `credential-master-rewrap` 必须提供稳定 rotation-id、刚核对的旧指纹、精确记录数量、独立新主密钥文件及原因。先认证全部记录，再在一个事务中写新密文、逐条摘要证据、代际和单条审计；任何失败全部回滚。上限10000条，表锁等待最多5秒，CLI总时限3分钟。
- rotation-id 固定整个操作输入；丢失响应时使用原rotation-id/旧文件/新文件/数量/原因重试，只返回既有已提交证据，不重复改写。输入变化返回冲突。`already_committed` 描述历史该次操作，不证明运行进程已切换或后续没有新的轮换。
- 正常建钥与轮换共享维护锁；注册新代际后旧主密钥不能继续创建混合代际。已登记的历史主密钥不能再当作新主密钥使用。撤销/安装事务通过现有数据库锁与维护串行，普通读取可完成既有快照；无半新半旧的已提交状态。
- 051只对密文存储维护放行：同事务存在匹配旧/新密文SHA256证据时才允许修改ciphertext，其余身份/撤销字段必须完全不变。逐条证据及批次不可更新/删除。keel_app对三个维护表仅SELECT，对ssh_domain_keys仍无写权限；维护还要求数据库owner/owner组成员或superuser身份。

## 实施顺序（仅适用于明确安排的维护窗口）

代码开发不执行下列生产操作。准备时须已完成迁移/权限验证、可恢复数据库备份及受保护旧主密钥的独立保留；旧备份仍依赖旧主密钥，不能因新代际提交就删除旧文件。

1. 暂停新SSH任务准入并安排worker/provider维护，保留运行任务与unknown隔离记录；升级owner CLI与schema051，旧二进制不能越过精确迁移检查继续写入。
2. 使用`credential-master-keygen --output <new-private-file>`独立创建新文件；已存在文件不覆盖。旧`KEEL_CREDENTIAL_MASTER_KEY_FILE`保持，执行`credential-master-inspect`取得一致快照指纹和数量。
3. owner执行`credential-master-rewrap --rotation-id <32hex> --expected-source-key-id <64hex> --expected-keys <count> --new-master-key-file <new-private-file> --reason <reason>`。异常不自动切换文件；响应不确定时保留两份文件和参数，用相同rotation-id确认提交结果。
4. 已确认提交后，将目标部署配置切换到新文件、重启读取主密钥的API/worker/provider，再用新文件执行inspect，并验证实际受限角色与SSH读取。旧进程后续无法解密新存储，必须显式完成切换；此命令不会重启服务或修改真实.env。
5. 验证完整后恢复准入；历史备份和旧密钥按独立保留政策管理。恢复旧数据库备份时必须配对其原主密钥；不能把旧文件直接指回已是新代际的数据库，也不删除目标公钥或已有回执。

新生成主密钥、数据库事务与部署文件切换不是一个原子操作，本功能使用维护窗口解决该边界；不宣称在线零停机双钥轮换。检查/CLI输出及审计只含非敏感操作元数据，运行环境变量和主密钥内容不得进入日志。
