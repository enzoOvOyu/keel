# P1 介质实际文件与批准读取

对应 PRD FR-1.8、ARCHITECTURE ADR-07/[I-2]、DESIGN-SYSTEM 介质库、IMPLEMENTATION-PLAN A4/WP-1.10、ACCEPTANCE F-1.6/F-1.8 的文件存储与读取部分；不是完整介质分发或 P1 验收。

## 已实现的链路

- 保留登记 API；新增 multipart 上传新版本，由服务端从文件实际计算 SHA256/大小。已有登记通过 PUT 附加与登记摘要/大小完全一致的文件；只能由原登记人附加，避免审批人上传后自批。
- 文件保存在配置的私有 MinIO 桶（默认 `media`），强制启用版本化；对象键由平台生成。039迁移的 `media_artifacts` 永久绑定对象版本、摘要、大小和上传人，数据库 trigger 拒绝更新/删除。重传/重复版本不能覆盖绑定；对象库管理员仍可删除版本，此时读取拒绝，不能冒充不可破坏存储。
- 校验、审批、下载均读取固定对象版本并核对实际字节、登记身份和绑定摘要/大小。仅 manifest 非空不再能通过；缺对象、错误摘要不批准、不返回制品字节。校验通过仍需独立 Admin/SRE 审批，摘要完整性不代表厂商来源签名可信。
- 所有 API 按当前会话与项目鉴权；Admin/SRE 管理，成员读取批准文件。全局介质可以按授权读取，不能从项目入口修改全局记录。审批前和退役后禁止通用下载；历史元数据/引用保留，不物理删除文件。
- 下载不暴露 S3 凭据或直连 URL，完整校验到600权限临时文件后，使用同一文件响应 HTTP Range/If-Range；返回摘要与 ETag，保留上传/校验/审批/下载/退役审计。临时文件完成或失败即清理。
- 现有介质页面提供上传新版本、附加登记文件、实际文件状态和批准下载，复用共享组件、确认弹窗、项目 URL、中英文和 Intel 字体。单次 inline 文件上限1 GiB、请求5分钟；不是容量/吞吐承诺。

## 接口

| 项目介质路径 | 行为 |
|---|---|
| POST `/projects/{id}/media/upload` | multipart `metadata` JSON 在前，`file` 在后；自动计算摘要/大小并原子保存登记、版本绑定与审计 |
| PUT `/projects/{id}/media/{mediaId}/content` | 原登记人上传 `application/octet-stream`，必须精确匹配原登记身份，绑定后不能替换 |
| POST `/projects/{id}/media/{mediaId}/transition` | 原状态机，校验与审批新增实际字节核对；不能跳态或自审批 |
| GET `/projects/{id}/media/{mediaId}/content` | 仅批准且未退役文件，项目鉴权、实际校验、审计和 Range；无对象版本时拒绝 |

正式契约见 `api/openapi.yaml`，前端类型由既有生成命令更新。`media:read/manage` 为独立会话能力，具体请求仍在事务里复核当前项目权限。

## 存储与部署

配置见 DEPLOYMENT §8；API 未配置存储时不伪造制品，文件操作返回不可用。操作员通过 `keel-admin media-init` 显式建立/启用版本桶，API不自动创建桶。桶初始化使用独立操作员权限；API服务账号仅需该桶的 GetBucketVersioning、PutObject、GetObjectVersion/相关对象读取权限，不授予删除版本或设置公共策略。生产要求 HTTPS。

上传对象存储成功而数据库提交失败时可能留下未引用对象；数据库记录不会假装成功，也不在异常路径冒险删除历史对象。未引用对象清理/保留制度、目标缓存、Agent/SSH推送、包管理镜像源、外链摄取、厂商签名/离线依赖闭包、持续损坏隔离治理与规模验收仍待后续实现。旧 approved 元数据不自动补造文件证据；直接文件读取仍须真实绑定。参数目录与通用 sim 执行创建的批准制品引用准入已接续，见 [CATALOG-ADMISSION](CATALOG-ADMISSION.md)；其他业务消费者及真实分发仍按各自阶段收口。

## 共享弹窗的 CSP 接线

真实浏览器发现 Radix 滚动锁动态样式被原严格 CSP 拦截。HTML入口（含 `/index.html` 和应用路由）现在获得每次请求独立的样式 nonce，React入口通过锁定的 `get-nonce` 传给共享组件。保持 `script-src 'self'`，不开放 `unsafe-inline`；nonce HTML使用 no-store，避免缓存串用。单测验证 nonce与CSP一致、每次不同且直接入口不绕过。

## 全局介质管理（A4 接续）

平台管理员系统入口 `/admin/media` 复用项目介质页面、弹窗与原服务事务，提供登记、文件上传、校验、独立审批、完整/Range下载和不可恢复退役。全局参数目录的登记链接进入该页；批准并具有实际绑定的全局制品进入版本默认值选项。上传者不能自行审批；只有原登记人可补传精确匹配的文件，绑定后不能替换。全局新增版本同样要求校验摘要/实际字节，未上传文件不允许校验，未批准/退役制品不能下载或作为新引用。

正式全局接口与项目路径同构：GET/POST `/api/v1/admin/media`，POST `/upload`，PUT/GET `/{mediaId}/content`，POST `/{mediaId}/transition`。服务端固定global作用域，不接受客户端scope_key；所有全局管理请求（含只读列表和下载）要求平台管理员，项目Admin/SRE/Viewer不能借项目权限进入。写操作在读取上传正文之前复核身份、CSRF/Origin和管理权限；nil项目的直接服务下载也复核平台管理员。

项目成员继续按项目授权查看/下载既有继承的批准全局制品，项目页面显式“全局 · 只读”并隐藏其管理动作；服务端原有跨作用域写拒绝保持。全局接口不能读取或修改项目自身介质。项目页面修改刷新当前项目的介质/目录查询，全局修改刷新当前用户的相关项目/全局查询；其他会话仍由服务端当前状态复核，未增加广播推送。

无数据库迁移或新存储配置，复用现有私有版本桶及受限账号。仍不提供外链自动摄取、厂商签名/离线闭包治理、目标缓存/真实大规模分发等后置能力，WP-1.10/1.11与P1仍partial。检查版本输入的登记例外仍精确限同一个RegisterMediaDialog字段，未扩大lint排除范围。具体实际验证、提交与3000状态见HANDOFF §35。


## 状态变更的陈旧确认保护

项目和全局的transition接口共用正式 `MediaTransitionInput`：`state`必填，可选 `expected_updated_at` 表示操作者确认时看到的介质版本。交互页面始终发送弹窗快照中的时间。服务端在既有鉴权和作用域复核、行锁内比较；时间不匹配返回409 `MEDIA_CONFLICT`，不改变状态/版本、不添加成功审计。旧状态即便仍允许退役，也不能跳过这个比较。页面保留确认对象和冲突提示，取消后刷新列表，再按当前状态重新确认；不会自动套用新版本重试。

实际文件补传和状态推进均严格递增updated_at，使用PostgreSQL持久化的微秒精度，成功响应直接返回实际存储的同一时间。即使文件补传没有改变uploaded状态，旧确认也已失效。CreatedAt、制品摘要/不可变对象版本及历史执行不改写。格式非法或零时间拒绝；省略条件的旧调用保留原单向状态机和独立审批行为，不能恢复退役记录。

本功能无新迁移，不实现介质修订浏览器、审批报告治理、真实分发或模板同步；WP-1.10/P1仍partial。实际并发PG、MinIO/API/双浏览器证据及发布状态见HANDOFF §36。

## 固定版本制品依赖（A4 / WP-1.10 接续）

`MediaDependencies` 在现有 `compatibility` 外增加可选 `artifacts`，每项输入精确的 `media_id` 和小写 `sha256`，不接受 `latest`、名称推测或运行时自动升级。登记时服务端从实际介质解析名称、类型、版本与架构，覆盖客户端显示元数据，随父介质不可变登记保存。参数键的依赖仍仅为兼容矩阵，不能混入制品引用。

```json
{"artifacts":[{"media_id":"0123456789abcdef0123456789abcdef","sha256":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"}]}
```

登记要求完整传递闭包已有实际文件且已批准，项目介质只能依赖同项目或全局，global只能依赖global；依赖架构必须与父项相同或为noarch。摘要必须匹配固定登记身份。最大32直接依赖、128传递依赖、16条边深度；共享节点去重但仍检查每条边和最长路径，拒绝循环与超限历史数据。`compatibility` 原有的精确版本/内核组合判据保留，两类依赖并存。

校验、独立审批、下载与执行准入重新读取整个闭包的当前批准状态、不可变对象版本和实际字节；其中任一退役、缺失、摘要不符或架构不兼容即拒绝，不返回未经验证的父文件。目录选择校验先检查闭包元数据，实际执行创建再验证固定对象字节；不因只携带父项摘要而跳过其依赖。检查期间保留数据库共享锁，避免退役与执行创建竞态。新版本不会替换旧引用；退役保留历史但阻断依赖方后续校验、审批、下载和准入，退役父项本身仍允许进行。

项目/全局登记弹窗复用已批准、已存文件、当前架构的版本选择，显示固定摘要、允许移除并禁止重复选择。审批弹窗列明固定依赖，列表显示直接依赖数；错误保留确认弹窗。继承全局项仍只读，服务端权限规则保持。未声明制品依赖的历史介质保留原行为，无新迁移。

这是已登记制品依赖闭包与完整性准入，不等同于已签名离线仓库manifest、厂商来源签名、包管理镜像源、目标缓存或规模分发验收。上述部分继续按WP-1.10后续任务开发，P1保持partial。验证与发布证据见HANDOFF §49。

## 有限读取重试与固定源隔离（A4 / WP-1.10）

平台读取已绑定的固定对象版本时，最多尝试3次完整读取，失败后的等待为100ms、200ms，并受调用方请求期限约束。对象存储SDK关闭额外HTTP重试，避免隐藏放大次数。每次都从固定版本开头重新读取并核对实际长度/SHA256，不切换到最新对象或其他介质。前两次摘要错误但第三次成功时可继续，成功后不保留隔离标记；传输失败、读取中断、请求取消都不能单独证明源摘要损坏。

同一次检查的3次尝试均完整读取且摘要/长度不符时，隔离该不可变源。首先回滚失败的校验/审批/下载/签名导出/执行准入事务，再以独立、最多5秒的完整性事务持久化隔离与 `media.quarantined` 审计。不能在马上回滚的业务事务里写一条随后消失的标记，也不能绕过自身生命周期锁启动相互等待的写事务。持久化失败返回503 `MEDIA_INTEGRITY_UNAVAILABLE`，不声称已成功隔离。首次连续错误响应为422 `MEDIA_DIGEST_MISMATCH`，后续直接访问为422 `MEDIA_ARTIFACT_QUARANTINED`，传递依赖为 `MEDIA_DEPENDENCY_QUARANTINED`，不再读取该源。

新增041迁移建立 `media_artifact_integrity`，为既有固定绑定补初始记录，并为新绑定同事务写入。初始未隔离不表示免除真实文件校验。隔离保留最后观察摘要/长度、固定对象版本、期望身份和3次完整错误的计数/审计；不存原始文件或存储凭据。已隔离证据禁止修改/删除，介质ID不可改。它独立于 `uploaded → verified → approved → retired` 生命周期，隔离不会伪造退役、批准或撤销历史执行。介质页面分别展示审批状态与隔离状态；恢复字节不自动解除隔离。恢复流程为登记新的不可变版本、上传匹配文件、校验并由独立复核者批准；旧版本仍可退役。

批准/分发/签名导出和执行准入都检查隔离状态；目录不再提供已隔离的根源版本，新制品登记不能引用隔离依赖。父制品保持原审批状态，但隔离的任意传递依赖阻断新引用。成功文件校验持有完整性行共享锁至外层事务完成，稍后的隔离写入须等待该次准入完成；并发隔离仅首个写入追加审计。ZTP现有生成管理脚本路径也拒绝显式隔离的批准引用；此约束不以补造尚未交付的全部源存储/PXE能力为前提。

本步覆盖平台到版本化存储的完整性读取与控制面准入；目标端Agent/SSH安装、apt/yum镜像、目标缓存和规模性能仍须后续实现，WP-1.10/P1保持partial。`--integrity-only` 隔离集成在一次性MinIO前使用仅测试进程可控的回环HTTP代理，翻转指定固定对象响应的一字节并保留真实存储版本，记录实际GET次数。真实PG/MinIO/API/浏览器的显式协议故障注入，与Go对象接口mock、存储介质本体损坏及真实目标验证分别计证，不混写。

## 受控 HTTP(S) 来源获取（A4 / WP-1.10）

登记时可在现有 `manifest_ref` 中填写HTTP(S)文件URL（仍须声明准确SHA256/长度）。URL不允许用户信息、查询参数或片段，最多200字符；含临时令牌的预签名URL不能作为不可变公开元数据保存，带凭据镜像须后续凭据引用适配，不能把秘密写进URL。普通来源清单说明仍可保留，但不能替代实际文件。

操作员可配置 `KEEL_MEDIA_FETCH_ORIGINS`：最多32个逗号分隔的准确origin，如 `https://mirror.example.internal`，可含显式端口，不能含路径/用户信息/查询/片段/通配符。默认空值关闭，不扩大运行服务器的外网访问范围。除显式development外只允许HTTPS且正常校验证书；内部CA须按受控主机信任配置，不提供跳过TLS校验的开关。内部私网镜像可按明确来源授权访问；DNS每次解析后验证地址并直接拨号该IP，拒绝未指定、组播、link-local、任意DNS名重绑定loopback，以及已知云元数据地址。loopback仅development且来源本身明确为localhost/回环IP时可用；不继承环境代理。

项目和全局同构 `POST .../media/{mediaId}/fetch`，不接受正文或客户端替换URL。复核会话、CSRF/Origin、Admin/SRE/平台管理范围及原登记人；继承全局项不能借项目路径修改。只对uploaded且未绑定的登记获取，已有固定文件/已推进状态拒绝且不再请求来源。每次最多3条来源获取链、链内最多3次重定向；每跳仍须精确允许的origin；整次请求最长5分钟，正文1GiB、响应头64KiB，拒绝压缩或部分内容响应。客户端不携带API Cookie/Authorization/CSRF。

字节先落600临时文件，最多读取登记长度加1字节（同时受1GiB上限约束）并计算长度/SHA，超出即拒绝而不读取任意大响应。只有与登记完全相符才复用既有版本桶绑定、完整性行和media.upload审计，另记media.source.fetch（仅origin/摘要/长度/尝试数，不记秘密请求头）。失败不绑定文件，不产生批准、校验或成功获取审计。未经绑定的外部错误不冒充已批准固定源损坏，不生成隔离证据。获取成功仍uploaded，需后续真实文件校验和独立审批；以后下载/执行都取固定存储版本，远端URL变化不能替换它。

共享登记/列表提供只读来源审核、目标/摘要/长度确认及中英文失败提示；非原登记人/只读成员不显示获取动作。无新增迁移，复用041后的绑定与完整性记录。它是凭据为空的受控HTTP文件摄取，不是apt/yum镜像同步、来源签名、目标端缓存/安装或规模证据。配置与实际发布状态分别留证，未提供受信来源时默认保持关闭。

云元数据拒绝地址根据官方资料核验：[AWS实例身份文档](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/retrieve-iid.html)、[Alibaba Cloud实例元数据](https://www.alibabacloud.com/help/en/ecs/user-guide/view-instance-metadata/)。

## 兼容矩阵文件导入与审核（A4 / WP-1.10、WP-1.11）

```json
  "combinations": [
    {"os.kernel": "kernel-a", "runtime.profile": "tool-a"},
    {"os.kernel": "kernel-b", "runtime.profile": "tool-b"}
  ]
}
```

示例值仅用于说明格式，不声明真实硬件或软件兼容。精确版本来自操作员提供的已复核矩阵，界面不内置厂商组合。必填source/version/report_ref，至少requires或combinations一项；requires最多32键、每键1..256个唯一精确值；combinations最多128行、各行相同1..32列，不允许重复行/未知字段/空值。组合必须整行匹配，不能从不同允许行各取一列拼成未验证组合。报告引用只显示为文字，不作为链接访问或自动取证。

文件发送到受会话、项目管理权限、Origin和CSRF保护的 `POST .../media/compatibility/validate`，复用登记时的同一后端校验器，不创建介质、不推进审批、不写成功登记审计。有效后显示来源、矩阵版本、报告及完整行表；校验中、JSON错误、过大文件或服务端拒绝时阻止登记。操作员可修正文件或显式移除，不能因错误默默丢弃矩阵继续提交。快速更换文件时取消旧请求并按选择序号丢弃过期响应。

确认后与固定制品依赖一起保存在不可变deps中，实际登记仍再次校验全部元数据。校验/审批及签名导出弹窗显示同一矩阵；列表“查看兼容矩阵”允许项目只读成员查看自身和继承全局项，不能编辑版本或批准。矩阵随当前介质版本固定，后续更改必须登记新版本。文件导入本身不证明来源、报告或硬件验证通过，继续需要实际字节校验、独立审批和执行时目录依赖准入。

`python3 scripts/check-media-artifacts-integration.py --matrix-only` 使用隔离PostgreSQL/MinIO/API及真实浏览器验证导入、快速切换、独立审批、Viewer只读及签名保留；完整集成也包含该检查。不把这一步当作完整镜像源、目标安装或P1签署。


## 介质查询与依赖候选分页

项目/全局列表支持 `search`（名称/版本的字面、不区分大小写子串，最多120字符）、`type`、`state`、`compatible_arch`、`stored_only`。百分号、下划线和反斜杠按字面搜索，不作为SQL通配符；SQL参数绑定，作用域条件用括号与所有筛选相交，不能借OR进入其他项目。查询计数与分页使用同一条件，稳定顺序追加ID。拒绝重复筛选参数、无效枚举/布尔值、无效UTF-8/NUL和过长查询。

`compatible_arch=amd64`包含amd64/noarch，arm64同理，noarch只包含noarch。`stored_only=true`只筛选根制品有固定文件且未隔离；不会免除完整传递依赖的当前准入，也不判断实际目标兼容。无筛选保留原列表语义，包括只读全局继承元数据；文件下载仍要求批准和实际校验。

共享页面提供名称/版本查询、类型、状态、适配架构及清空筛选；改变筛选回第一页。固定制品选择器在服务端按approved/已存文件/未隔离/适配架构先过滤再分页，查询缓存包含架构，切换架构回第一页并保留已选不兼容依赖的明确错误。目录管理的批准介质来源也在分页前排除未批准/未存储/隔离根源，前端继续检查；不把当前列表中的某个可选版本升级成免复核的默认信任。

`--filters-only` 隔离验证25条排在前面的草稿不会挤掉实际可用候选，并覆盖字面搜索、准确分页/计数、项目/全局和只读权限、中英文以及架构切换；完整模式也包含该验证，真实PG额外检查隔离根源不会进入存储候选。

## 查看持久隔离证据

项目和全局 `GET .../media/{mediaId}/quarantine-evidence` 查询已持久化的隔离记录，返回介质ID/当前审批状态、固定对象版本、期望与末次完整失败观测的SHA256/长度、隔离记录时间、原因及连续失败次数。它只读数据库，不重新读取对象存储，不解除隔离，不以当前恢复后的字节替换旧证据；没有隔离记录或越出当前作用域返回404。状态是当前介质生命周期，其他隔离字段保持不可变，退役后仍可追溯。观测值取首次成功持久化隔离的那组3次完整失败中的末次读取；并发隔离或以后请求不会覆盖它，因此不是当前存储状态。

项目成员含Viewer可查看本项目和继承全局记录；全局管理入口仍仅平台管理员。返回private/no-store及nosniff，不含对象key、桶凭据、原始文件、内部会话或私钥信息。它只提供固定源摘要不符的观测记录，不单独诊断存储硬件或厂商来源。

共享列表的“查看隔离证据”显示同一份记录，并明确区分期望文件与最后一次完整读取；支持中文/英文、错误重试和随时关闭。没有解除/重置或直接重试源的动作。恢复仍按既有规则退役旧版、登记校验新版本并由独立人员审批；历史隔离记录不删除。

## OS 引导组合（WP-1.10 → WP-1.7，2026-10-25）

本次输入为现有不可变介质版本、固定依赖闭包、审批/RBAC及实际对象校验；输出是可由后续装机消费的完整 OS 角色组合及只读核对界面。它不依赖尚未开发的 PXE、安装回调或 G3，也不启动装机。

工程契约：`deps.os_boot` 使用 `keel.os-boot/v1`，当前 installer 为 `cloud-init`。当前介质自身为 rootfs，必须 type=os、arch=amd64/arm64；kernel_media_id/initrd_media_id/template_media_id 必须是三个不同的直接固定依赖，摘要来自同一 `deps.artifacts`，不解析 latest、URL 或自由文本。kernel/initrd 为相同具体架构的 os 制品，template 为兼容架构的 config 制品（可 noarch）。角色是已审批元数据，不以文件扩展名证明镜像可启动。已登记的普通 os 制品仍有效，但没有角色组合就不能解析为完整安装镜像。

登记即校验角色、作用域及依赖；验证、审批、读取、参数准入和签名导出复用同一闭包检查，依赖退役/隔离/摘要不符会阻断。角色组合随现有不可变 deps 保存，修改必须登记新版本并重新审批。签名清单增加可选 os_boot 字段并覆盖签名和严格字段验证；旧清单未配置时编码不变，旧版严格校验器会拒绝含新字段的清单，离线使用前升级校验器。

新增 GET `/api/v1/projects/{id}/media/{mediaId}/boot-profile` 和全局对应路径：当前项目成员/全局平台管理员读取，返回四个角色的固定 media_id、摘要、架构、大小与对象版本。响应不含对象键、S3地址或下载凭据，不授予匿名读取；完整对象和依赖在本次读取中重新核对，启动装机仍须在准入事务重新检查。页面仅从介质库已批准依赖下拉选择角色，提供独立核对结果及失败状态。

本批 Go 编译及生成后 TypeScript 检查通过；新增数据库/签名故障用例已写入，按用户要求留待 P1 集中运行。ProxyDHCP/iPXE、cloud-init 安全渲染、一次性回调、首连互信及装机七阶段仍未完成；F-2.2~F-2.6 和 WP-1.7 保持 partial。


### 可选的实际启动配方

OS的`os_boot.recipe`现在可固定`keel-initrd/v1`/squashfs协议，以及直接依赖中的同架构UEFI、可选amd64 Legacy固件、预检helper和SSH helper（精确ID/SHA256）。原四角色准备预览兼容；有配方返回7～8角色。扫描/登记角色、签名清单、当前生命周期及实际字节校验共同保护整个闭包，任意固件/helper不能作为默认内置未审核文件。配方与固定版本可在既有介质页选择，helper摘要来自所选依赖。自定义initrd的可启动性/驱动/写盘前预检仍须独立验证；不是通用ISO自动安装支持。具体协议及剩余接线见PROVISIONING。


### 独立 helper-set 与离线 installer overlay

安装helper先独立登记/批准，再由同架构config介质（`keel.installer-helper-set/v1` JSON）显式绑定恰好两份直接依赖及其ID/摘要；该config不引用最终initrd/OS，避免镜像输入与最终配方循环。导出其签名清单和原字节后，`keel-admin provision-overlay-create`生成可审核gzip/newc只读helper包，`provision-overlay-verify`独立信任公钥并反向核验完整归档/配置/ELF/实际摘要，无宿主解包或二进制执行。生产镜像之后才把最终initrd及helper版本固定到OS配方。完整步骤见PROVISIONING；离线历史审批与包校验不代表当前线上批准或可启动镜像验收。


## 批准任务脚本用途（2026-10-26，源码未验证）

工具登记/上传表单可显式选择 Shell/Python 脚本用途，保存于 `deps.task_script={"version":"keel.task-script/v1","interpreter":"shell"}`（或 python）。该声明属于独立审批的不可变元数据，不能复用 `manifest_ref`：上传仍由服务端写入 `artifact:sha256:<实际摘要>`，外链仍保留来源URL。只有用途、noarch/Linux、1～8192字节、无硬件范围/依赖/兼容矩阵/OS boot的工具才能用于本有界脚本执行。未知用途字段、任意解释器路径、空profile及超限拒绝登记，普通工具不因文件扩展名或manifest文本自动变成可执行脚本。

选择脚本用途会清空并固定不支持的范围/依赖条件；审批对话框展示执行用途，仍禁止上传者自行批准。SSH/Agent候选目录及实际派发以独立profile筛选/校验，冻结的版本/实际对象/摘要/大小/批准身份不变。已有普通上传/外链获取逻辑保持，未新增迁移。此链路及新增登记边界/实际上传摘要与用途并存用例尚未集中验证。
