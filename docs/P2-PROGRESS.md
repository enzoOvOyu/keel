## 下一开发顺序

1. 先接WP-2.4/2.13的共同Execution准入、worker路由、全范围独占/取消与原runner回执消费。用模拟驱动推进软件流程，保持sim/protocol_fixture来源；真实特权helper不通过普通非root SSH偷偷sudo，也不迫使软件开发等待硬件PoC。
2. 从已完成原回执消费Step2/3，保留source hash、前驱/版本和范围失效；失败或缺测阻断后续，接T1/T2/T6工单与限定重跑。
3. 接DL Step4确认有效结果，原子形成G2及NP-3。随后按WP-2.5发布G3 Mapping，复用既有PhysicalPort身份，不能从邻居反向创建预期。
4. WP-2.10在其现有前置具备后可独立开发；portmon随后消费G3/监控。再接门禁豁免/KPI和完整服务器详情抽屉。没有P3的NP-5/6不应反过来阻挡当前G2开发。
5. 按用户要求在重大软件里程碑集中验证，不逐小步重建镜像或浏览器复验；源码、模拟软件结果、真实PoC、运行版和验收分别记录。

当前内部Run/Query只接受已注册的共同执行命令，尚无实际创建/worker入口。数据库085继续拒绝Step2～4；没有G2、NP-3或G3已发布的结论。原fabric_precheck两份草稿保持隔离，禁止纳入迁移或提交。
