# H-15 真实 BOM 导入执行包

本包供所有者在独立 PoC 项目执行，当前未执行。只完成材料不代表 H-15 或 P1 PASS。产品格式以 PRD FR-2.1/附录A、实施计划 WP-1.15/1.16 和正式 API 为准。

准备设计院/网络团队原始 BOM、字段字典及真实表头别名；保留来源、版本、批准引用和原始文件 SHA256。另准备批准的字段映射版本、有效型号版本及独立项目。秘密、口令、Cookie、私钥和含凭据的 HAR 不进入证据包；BOM 凭据只保留平台支持的引用元数据。先确认采用的源码已统一验证并部署，不能用旧3000镜像验证新增功能。

1. 在项目 BOM 页面导入真实目录包：manifest.json schema v1、逐实体 CSV、映射与规范化摘要按正式契约准备。若原始来源为宽表，保留原件，另记录目录转换过程；不伪装成第二份独立现场输入。
2. 只读预检，保存实际响应/界面及版本引用，确认没有提前写入资产。人工核对行数、SN/MAC、归属、型号、端口父实体、位置和线缆两端；未知型号/重复标识/批次冲突等须按正式判据阻断。
3. 明确确认后提交一次，保存 commit、批次与审计。重复同一批准输入，核对幂等、零重复和原 UID；另用真实宽表及真实别名映射复现相同设备折叠。型号约束、版本与历史不能被静默改写。
4. 从原输入复制负例，只修改受控字段，保留来源/修改说明及摘要。覆盖文件、数据行、字段三级问题定位和 CSV 导出；将问题清单返回设计院，记录其复现/修订引用。负例不能覆盖已提交原件。
5. 使用无该项目权限的测试账号验证隔离，保存脱敏拒绝记录；不让证据包含会话或认证头。核对新导入和历史查询仍仅显示获授权项目。
6. 在仓库外私有目录复制 evidence.template.json 为 evidence.json，逐项填写真实文件路径/SHA和观察计数。运行 `python3 /opt/keel/poc/bom-h15/validate.py /path/to/evidence.json` 只检查完整性与文件摘要，输出 READY_FOR_REVIEW 后仍需人工审查 CHECKLIST.md。

开发软件回归入口为 `scripts/check-bom-import.py`/`scripts/check-bom-browser.mjs` 及平台 BOM 用例；它们的合成样本结果不能当作本次真实来源 H-15 证据。缺原始来源、三级定位回传或人工实物核对时记录 BLOCKED，保留责任人与待补信息。
